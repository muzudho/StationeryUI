# 開発日誌：2026年9月

## 2026-09-21

### スタイル設定から画面を組み立てる仕組み

- スタイル JSON を `models`・`layouts`・`bindings` に分離した。文房具の親子関係とレイアウトの構造を独立して定義し、bindings で接続する。
- px と小数を含む rate によるフローティングレイアウト、水平・垂直のスプリットペーン、開閉可能なツリーとドラッグできる縦スクロールバーを追加した。
- トップデモページとスプリットペーンデモページを、下線付きのリンクで行き来できるようにした。
- フルスクリーンと作業ページのレイアウトを追加した。作業ページには下部 80px のインスペクターパネルと、操作対象の説明を示すツールヒント欄を置く。
- 下線付きテキストの編集・ページ移動と、Edit／Popup／Move バッジの使い分けを利用者・開発者向けに記録した。

### 文房具 UI 自身を使う開発者ウィンドウ

- F12 開発者ウィンドウを文房具 UI で構成した。ツリーで文房具 Id・完全パスを選び、詳細・座標を確認し、パスをコピーできる。
- 別プロセスの MonoGame ウィンドウと名前付きパイプで接続し、選択・開閉状態・分割比率を保持する。
- 専用の `App_Data/dev-window.stationery-style.json` に配置を切り出した。配布時は JSON を DLL に埋め込み、外部ファイルがなくても使える。
- UI の描画・入力・フォーカスを管理するクラス名を `DesktopUi` から `StationeryUiHost` に変更した。ライブラリー全体とホストの役割を名前で区別しやすくした。

### スタイル設計ツール v0.1.0

- C# の実装を AI コーディングへ任せるため、GUI で画面のプランを作り、スタイル JSON を出力する独立アプリを作成した。文房具 UI の NuGet パッケージには設計ツールを含めない。
- １ページ目で新規作成／既存ファイルの読み込みを選択し、２ページ目で左のスタイルツリーと右の表を見ながら編集する。
- 新規作成では最大 8×8 のセル、文房具の種類・表示名、行列のサイズを設定できる。数値と rate／px の単位は別々に入力・選択する。
- 既存ファイルではフローティングレイアウトのサイズを編集できる。モデル、bindings、ほかのレイアウト、追加プロパティを保持し、編集結果は別名で出力する。
- 操作ボタンを文房具 UI の共通の枠付き描画にし、下線付き入力欄と区別した。既存ファイルは Windows のファイル選択ダイアログで選択できる。
- 編集モデルの検査を含む 27 件の自動テストと、新規作成・既存編集・ネイティブダイアログの選択／キャンセルの GUI 検査を実施した。
- CircleSpaceCoordinator の配布資料を参考に、ランタイム同梱の Windows x64 ZIP、展開後の起動確認、チェックサム、ダウンロード案内を含むリリース手順を整備した。設計ツールは v0.1.0、既存ライブラリーのタグと区別するリリースタグは `style-designer-v0.1.0` とする。

操作方法は [スタイル設計ツール](../../../user/style-designer.md)、配布方法は [設計ツールのリリース手順](../../style-designer-release.md) を参照。

### アクションバッジの調査とデモ拡充

- きふわらべのホバー時の角丸バッジが `ActionBadgeComponent` として移植済みであることを確認した。元アプリでは数値編集ダイアログにも `EDIT` を指定していた。
- デモの入力欄に `EDIT`、ダイアログ起動項目に任意ラベルの例として `POPUP` を追加した。保存・キャンセルと背景の入力遮断を接続した。
- バッジの位置・サイズをStationeryUiHostの拡大率に合わせた。
- [バッジの解説と確認手順](../../action-badges.md) を追加した。
