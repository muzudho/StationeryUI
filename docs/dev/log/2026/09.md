## 2026-09-26 — ビュー設定とレイアウト記法の整理

- `viewports` の各ノードに `type` と子要素の `place` を持たせ、子要素の配置を親の `layout` で指定する形式へ整理した。`ViewNode` のツリーからビュー構成を読み込み、レイアウト設定とモデルツリーを分けて扱う。
- JSON フォーマッターを追加し、子を持たないオブジェクト／配列を短い場合は1行にまとめるようにした。レイアウトの `colspan` と `rowspan` は値が `1` のとき出力を省略する。
- 設定内容がスタイルだけでなくビュー構成・配置・モデル参照を含むため、設定ファイルの拡張子を `*.stationery-style.json` から `*.stationery-ui.json` に変更した。デモ、開発者ウィンドウ、既定設定、デザイナー、読み込み処理、テスト、ドキュメントの参照を更新し、ユーザー向けガイドも `stationery-ui-settings.md` に改名した。
- レイアウトデザイナーが新しい仕様に未対応のため、今回はバージョンを上げない。フレームワークとレイアウトデザイナーの両方が新仕様に揃った段階で、同時にバージョンを上げる。

### レイアウトエディターの参照対応と編集ページへの遷移修正

- 文房具 UI ファイルを選んでも開始ページから切り替わらない問題を調査した。操作ログではファイルを開くボタンのクリックまで届いていたが、ページ遷移は記録されていなかった。同梱の `demo.stationery-ui.json` を使って、ライブラリー本体の解析は成功し、エディターの解析だけが `Layout name is missing.` で失敗することを再現した。
- 原因は、エディターが `layout: { "ref": "grid" }` をレイアウト定義として扱い、参照には存在しない `name` を要求していたこと。`StyleBlueprint.LayoutNodes` で定義と参照を区別し、参照先となる入れ子の定義を完全パスで列挙するようにした。参照自体は定義として重複登録せず、読み込み・編集・再出力で保持する。
- 読み込み後のプレビューでも、複数ページで共有するコントロールに `LayoutKey` が必要となる問題を確認した。プレビュー対象ページ内のモデルに対応する経路を選び、レイアウト計算へ渡すようにした。
- 新形式のファイルを開き、参照先のグリッドを編集して再度読み込めること、対象以外の設定や参照が保持されること、各グリッドのプレビューと共有コントロールの経路選択を検証する回帰テストを追加した。
- Release ビルドは警告 0・エラー 0。追加した回帰テストは成功し、GUI の検査でも編集ページへの遷移、ツリーとプレビューの表示を確認した。ただし、GUI 検査スクリプトの出力検証には旧 `layouts` 形式を前提とする処理が残り、スクリプト全体は失敗した。
- 自動テスト全体は 33 件中 23 件成功。旧形式を前提とする検証などで 10 件の失敗が残っている。今回の修正は読み込みと参照先編集の対応であり、新仕様への全面移行と検証コードの更新は引き続き進める。

## 2026-09-25 — bindingsV2 の段階移行

- Demo の画面コントロール bounds を `bindingsV2` から取得する形に統一した。V2 の bounds がない場合に旧 `Bounds` へフォールバックせず、設定漏れをエラーとして検出する。分割ペイン自身の bounds も V2 を使う。
- Demo の画面コントロール検証を V2 基準へ移し、各ハンドルが存在し、対応するモデルへ解決されることを検証する。ページのインスペクター配置や分割ペインの構成など、レイアウト構造に関する旧 `bindings` の参照は残した。
- `bindingsV2` の経路から対象モデルを設定読み込み時に解決し、`Arrange` は解決済みモデルの bounds をハンドルへ返すようにした。これにより、毎フレーム全モデルと経路を照合する処理を外した。
- コントロールハンドルの文字列からモデル Id を推測する制約を外し、レイアウトパスで対象モデルを決めるようにした。`ctrl` 接頭辞は慣習とし、MonoGame の `Element` はモデル Id を使った既定ハンドルを生成する。
- V2 必須化後に、Demo の埋め込みフォールバック設定にも V2 経路が必要なことが分かったため、画面コントロールとページ別パスを追加した。
- `ctrlSpanCell` の経路を実配置の `rowspan: 2` に合わせた。画面が描画された後に操作不能となる現象は、配置経路の検査中に発生して捕捉される例外で Visual Studio が停止していた。対象外モデルも照合して例外を発生させていた処理を除き、さらに経路解決を設定読込時へ移した。
- 設定ファイル形式の説明を現在の併用状態に合わせて更新した。配置計算と一部の構造検証は引き続き旧 `bindings` を使う。
- Demo の Release ビルドを確認し、成功・警告 0・エラー 0。フォールバック JSON の構文と V2 マッピングが `App_Data/demo.stationery-style.json` と一致することも確認した。

### スタイル設定エディター v0.2.0 — レイアウト設計と保存の改善

- リポジトリーの README 冒頭に、MonoGame でゲームよりもツール向けのクロスプラットフォーム GUI を目指す方針を明記した。CircleSpaceCoordinator の案内を参考に、ユーザー向けの起動手順と開発者向けの説明を分けた。現在の配布版は Windows x64 向けで、他 OS 対応の目標とは区別した。
- 読み込み時の `.N.bak` セーブポイント、最後の変更から1.5秒後のオートセーブ、最大20世代の保持、変更日時付き一覧からの復元を追加した。インスペクターにタイマーバーと保存状態を表示し、保存失敗や外部更新では入力を保持する。
- ツリーの「選択」は緑の背景、「操作対象」は水色の枠として分離した。エディターでは操作対象を使い、初期表示するレイアウトと水色枠を一致させた。対象がない場合は設定欄とプレビューを空にする。
- layouts の子要素として panel と floating-layout を追加できるようにした。Id の入力・変更、兄弟間の重複拒否、camelCase や数字始まりへの警告、margin・padding・border の編集を追加した。border は全体サイズに含めない。
- 現在の編集画面を layouts 専用に整理し、models と bindings は閲覧専用にした。レイアウトId変更時の参照更新は継続する。列数・行数は自動反映し、縮小時は確認する。
- 配置プレビューを実際のスタイル定義から作成し、ウィンドウ右端とインスペクター直前まで拡大した。対象Idとプレビューのピクセルサイズを表示する。
- 上部40pxのアプリケーションバー、下部80pxのインスペクター、出力先操作をまとめたエクスポートダイアログを導入した。操作説明はホバー時のツールヒントに集約した。
- ダイアログに半透明の黒い幕と枠を追加し、マウス・キーボード入力をモーダル内に限定した。最初のページは「スタイル設定ファイル選択」とし、ボタンを縦一列に中央へ配置した。
- 起動ウィンドウをタスクバーを除いた作業領域に収めた。小さな文字画像の縮小で細い線が欠けていた問題を、実表示ピクセルサイズでの描画に変更して修正した。ダークモードでも文字を読めるようになった。
- リリースタグは `style-designer-v0.2.0`。エディターとライブラリーのバージョンは別管理とし、Windows x64 用ランタイム同梱 ZIP と SHA-256 を配布する。検証と配布の記録は [v0.2.0 の配布記録](../../distribution/style-designer-v0.2.0.md) にまとめる。

### スタイル設定から画面を組み立てる仕組み

- スタイル JSON を `models`・`layouts`・`bindings` に分離した。文房具の親子関係とレイアウトの構造を独立して定義し、bindings で接続する。
- px と小数を含む rate によるフローティングレイアウト、水平・垂直のスプリットペーン、開閉可能なツリーとドラッグできる縦スクロールバーを追加した。
- トップデモページとスプリットペーンデモページを、下線付きのリンクで行き来できるようにした。
- フルスクリーンと作業ページのレイアウトを追加した。作業ページには下部 80px のインスペクターパネルと、操作対象の説明を示すツールヒント欄を置く。
- 下線付きテキストの編集・ページ移動と、Edit／Popup／Move バッジの使い分けを利用者・開発者向けに記録した。

### 文房具 UI 自身を使う開発者ウィンドウ

- F12 開発者ウィンドウを文房具 UI で構成した。ツリーで文房具 Id・完全パスを選び、詳細・座標を確認し、パスをコピーできる。

### スタイル設計ツール v0.1.0

- C# の実装を AI コーディングへ任せるため、GUI で画面のプランを作り、スタイル JSON を出力する独立アプリを作成した。文房具 UI の NuGet パッケージには設計ツールを含めない。
- １ページ目で新規作成／既存ファイルの読み込みを選択し、２ページ目で左のスタイルツリーと右の表を見ながら編集する。
- 新規作成では最大 8×8 のセル、文房具の種類・表示名、行列のサイズを設定できる。数値と rate／px の単位は別々に入力・選択する。
- 既存ファイルではフローティングレイアウトのサイズを編集できる。モデル、bindings、ほかのレイアウト、追加プロパティを保持し、編集結果は別名で出力する。
- 操作ボタンを文房具 UI の共通の枠付き描画にし、下線付き入力欄と区別した。既存ファイルは Windows のファイル選択ダイアログで選択できる。
- 編集モデルの検査を含む 27 件の自動テストと、新規作成・既存編集・ネイティブダイアログの選択／キャンセルの GUI 検査を実施した。
- CircleSpaceCoordinator の配布資料を参考に、ランタイム同梱の Windows x64 ZIP、展開後の起動確認、チェックサム、ダウンロード案内を含むリリース手順を整備した。設計ツールは v0.1.0、既存ライブラリーのタグと区別するリリースタグは `style-designer-v0.1.0` とする。

操作方法は [スタイル設計ツール](../../../user/style-designer.md)、配布方法は [設計ツールのリリース手順](../../style-designer-release.md) を参照。
