# F12 開発者ウィンドウと文房具UIエディターの統合計画

この計画の第1段階を実装した。デモからの F12 読取と Ctrl＋F12 編集は同じ `StationeryUIEditor` を使い、単独起動の読取モードも追加した。以下には最終形の設計と、残る作業を併記する。

## 採用する構成

**残すアプリは文房具UIエディター。** F12 開発者ウィンドウのモデルツリー、レイアウトツリー、詳細、キャプチャー、画面上の枠、パスのコピー、ライブ更新は、エディター内の「検査」機能として残す。既存の `StationeryDeveloperView` をもう一つの `Game` として埋め込むのではなく、検査モデルと必要な表示部品をエディターの画面へ移す。エディターのプレビューと、実行中アプリから届く検査結果は別のデータとして扱う。

`StyleBlueprint` と `StyleSaveSession` はエディター側に置き、文房具UIライブラリーには移さない。NuGet を利用するアプリにエディター本体の参照を要求しない。現在の `StationeryDeveloperWindow` は当面ホスト側の互換窓口として残し、内部の起動先を統合エディターへ切り替える。機能が揃うまで既存の `InspectorGame` と F12 経路を消さない。

## 起動とモード

| 起動・操作 | 最初の画面 | ファイルへの書き込み |
| --- | --- | --- |
| エディターを単独で引数なし起動 | 「新規作成」「ファイルを開く」の開始画面 | なし |
| 単独起動から「新規作成」 | 保存先未定の新規下書き | 保存先を決めた後、明示したファイルにだけ保存 |
| 単独起動から「ファイルを開く」 | ファイルの読取モード | なし |
| アプリから F12 | 実行中アプリにつながった読取モード。現在のファイルも開く | なし |
| アプリから Ctrl＋F12 | 同じアプリにつながった編集モード。現在のファイルを開く | 現行の検証・セーブポイント・オートセーブに従う |

読取モードではモデル／レイアウト／JSON のツリー、詳細、コピー、プレビューを使える。ライブ座標・表示状態・キャプチャーはアプリと接続している間だけ使える。編集欄、ページ追加・削除、復元、保存系の操作は使えない。ファイルを読むだけでセーブポイントやバックアップを作らず、ファイルの更新日時も変えない。操作ログは従来どおり別のログ領域に記録してよい。

ホストがファイルを持たない、またはファイルを読めない場合の F12 は、ライブ情報だけの読取モードで開く。ファイルを開けない理由を表示し、Ctrl＋F12 でもそのファイルの編集を始めない。ライブ検査そのものは続けられるようにする。

単独の読取モードからは、明示的な「編集を開始」で編集モードへ移れる。その時点でファイルの再読込と外部変更の確認を行い、編集セッションと最初のセーブポイントを作る。単独起動で新規作成を選んだ下書きは編集可能だが、保存先を選ぶまで既存ファイルに書き込まない。

現在の位置引数 `StationeryUIEditor.exe <file>` は、既存の呼び出し元を壊さないため移行期間中は従来の編集起動として扱う。新しい起動元にはファイル、`read`／`edit`、ライブ接続の有無を明示する引数を使う。位置引数を将来どう廃止するかは、利用箇所を調べてから別途決める。

## ウィンドウとモード切替

同じアプリ・同じ文房具UIファイルに対してはエディターウィンドウを一つ再利用する。F12 は読取モード、Ctrl＋F12 は編集モードで前面に出す。別のファイルや別のアプリは混同せず、接続元とファイル名を常に表示する。

編集から読取へ戻るとき、保存待ちの変更がなければそのまま切り替える。保存待ち・入力エラー・保存失敗がある場合は、保存、下書きを破棄、切替を取り消す、の選択を求める。保存に失敗した場合や切替を取り消した場合は編集モードに留まる。未保存の内容を暗黙に捨てたり、読取モードへの切替を理由に保存したりしない。ファイルや接続元を切り替える場合も同じ保護を使う。読取から編集へは明示した操作か Ctrl＋F12 だけで移る。

ホストアプリが終了したらライブ接続が切れたことを表示し、ファイルの読取・編集中のウィンドウは残す。以後の座標や表示状態は「最後に受信した値」と明示し、キャプチャーを無効にする。未保存の下書きがあるエディターを親プロセスが強制終了しない。

## データと通信の境界

文房具UIファイルは**編集対象の設計データ**。検査スナップショットは**実行中アプリから受信する観測データ**で、ファイルには書き込まない。両者が食い違うことはあり得る。例えば編集中の JSON が未保存、または保存後の再読み込みをアプリが拒否した場合、画面にはその差とエラーを表示する。実行中の座標から JSON を自動修正しない。

ホスト側は現在使っているファイルの絶対パス、接続 ID、検査スナップショットをエディターへ渡す。既存の同一ユーザー限定の名前付きパイプとスナップショット更新を土台に、プロトコルの版と接続状態を追加する。パイプは観測情報とキャプチャーの選択状態を運ぶ。**ファイル書込コマンドをパイプ経由でホストに実行させない。** 編集モードの保存はエディターの `StyleSaveSession` がファイルの外部変更検査と原子的な置換を行い、ホストは既存のリロード機構で反映する。

選択の引き継ぎには単なる Id ではなく完全なモデルパスとレイアウトパスを使う。JSON ツリーのノードに対応するライブ要素がない場合は「未接続」、ライブ要素にファイル上の対応がない場合は「実行時のみ」と表示する。読取／編集の切替でも、可能な限り選択ノード、ツリーの開閉、分割比率を保持する。

## 機能を移す順番

1. **共通の状態と起動契約を定義する。** `Welcome`、`NewDraft`、`ReadFile`、`ReadLive`、`EditFile` を分け、読取中に保存セッションが生成されないことを先にテストする。新しい起動引数を追加し、現行の位置引数は互換維持する。
2. **読取画面をエディターへ組み込む。** エディターが既に使う `DeveloperInspectionModel` のモデル／レイアウトツリーを基礎に、開発者ウィンドウの詳細、ライブ座標、キャプチャー、枠表示、コピー、状態保持を統合する。二つのツリー実装を無理に一度に置換せず、表示と状態が揃ったところから共通化する。
3. **ライブ接続を移す。** エディターがスナップショットを受け取れるようにし、F12 を新しい読取経路へ切り替える。通信断、ウィンドウ再表示、複数ホスト、パスの不一致を検証する。既存の F12 経路は、この段階では戻せる状態で残す。
4. **編集モードを接続する。** Ctrl＋F12 を統合エディターの編集経路に切り替え、オートセーブ、セーブポイント、外部更新検査、アプリ側リロード結果を画面に表示する。F12 と Ctrl＋F12 の切替で下書きが失われないことを確認する。
5. **旧ウィンドウを整理する。** F12 の機能と操作性が揃い、デモと NuGet 利用アプリ向けの移行手順ができてから、`InspectorGame` の独立 UI を廃止する。`StationeryDeveloperWindow` の公開 API は互換アダプターとして残すか、次の破壊的バージョンで段階的に廃止する。

## 完了条件

- 単独のファイル読取と F12 読取で、ファイル本文・更新日時・バックアップ数が変わらない。
- F12 で従来のモデル／レイアウトツリー、詳細、キャプチャー、画面上の枠、パスのコピー、ライブ更新を使える。
- Ctrl＋F12 で同じファイルを編集でき、保存成功とアプリ側の反映成功・失敗を別々に確認できる。
- 読取／編集の切替、通信断、外部ファイル変更、保存失敗で下書きと選択状態が意図せず失われない。
- エディター未配置の既存 NuGet 利用アプリについて、旧 F12 経路を残す期間と移行方法が文書化されている。

## 2026-09-26 の進捗

- `StationeryUIEditor` に開始画面、ファイル読取、ライブ読取、ファイル編集の起動経路を追加。旧位置引数は編集起動として維持した。読取では `StyleSaveSession` を作らず、ファイルとバックアップを変更しない。
- `StationeryDeveloperView` をエディターの読取画面に組み込み、既存のモデル／レイアウトツリー、詳細、キャプチャー、状態の復元を使う。デモはエディターを発見した場合、F12 と Ctrl＋F12 で一つの接続・ウィンドウを再利用する。エディターがない環境では従来の独立ウィンドウを使う。
- 読取から編集は明示操作または Ctrl＋F12 で切り替える。編集から読取で保存待ち・不正入力・保存失敗があれば保存／破棄／取消を選ぶ。ホスト終了時にはエディターを強制終了しない。
- 起動、読取時の無書込、同じプロセスでの F12→Ctrl＋F12→F12、従来の編集と旧開発者ウィンドウの動作をテストする。
- 読取画面に編集プレビューと同じ明るい配色を適用し、実行中アプリの対象枠・margin 境界・レイアウト分割線をプレビューと共通の描画関数に統一した。水色の太線が対象、水色の細線が margin の外側、桃色の点線が分割線。margin／padding の読取図と編集入力欄は、それぞれのモードの役割に合わせて残す。
- 読取画面の右側へ実際のレイアウトプレビューを追加し、詳細との切替を用意した。選択した子の水色枠に加え、親要素の桃色枠と親レイアウトの桃色点線を編集プレビューと共通の計算・描画で表示する。ファイル更新時も読取プレビューを再生成する。
- ライブ検査データにも親要素の枠と親レイアウトの分割線を添付し、デモ画面上の枠表示でも同じ親／子の色分けを使う。
- 編集画面の上部にアプリ側の反映状態を独立表示した。実行中アプリが最後に受理した文房具UIファイルの内容指紋とディスク上のファイルを比較し、「反映済み」「再読込待ち」「再読込失敗」「別ファイル」「接続終了」を区別する。読取画面にも接続状態を表示する。
- 読取画面と編集画面の切替時に、モデル／レイアウトツリーの選択パス、表示モード、枝の開閉を引き継ぐ。読取から編集へ移る際、既定のレイアウト選択よりも読取画面で選んだ対象を優先する。JSON ツリーの選択は対応するモデルパスがない項目もあるため、この引継ぎの対象外とする。

残る作業は、読取画面での JSON ツリー表示と JSON ノードの選択対応、通信断や複数ホストと外部変更時の対話の追加検証である。これらが揃うまで旧 `InspectorGame` は削除しない。NuGet 利用アプリは `StationeryDeveloperWindow.UseEditor(executable, filePath)` を明示すれば統合経路を使える。未設定のアプリは旧 F12 経路を使い続ける。

利用方法は[F12 開発者ウィンドウ](../../../user/developer-window.md)と[文房具UIエディター](../../../user/ui-editor.md)を参照。
