# レイアウトのネストとセル範囲指定の仕様案

相談中の拡張仕様です。現行のパーサー・配置エンジン・エディターには、ここで示す `layouts.children`、ドット区切りのレイアウトパス、`rowspan`・`colspan` はまだ実装していません。現行仕様は[設定ファイルの読み方](file-format.md)を参照してください。

## 拡張の方針

- `layouts` の各レイアウトは、`children` に子レイアウトを持てるようにする。
- padding は、そのレイアウトに割り当てられた領域の内側に取る余白。子レイアウトを含むコンテンツは、padding を除いた内側領域へ配置する。
- `bindings.layout` は `demoViewport.inspectorContents` のように、最上位からのドット区切りのパスでレイアウトを指定する。
- 子レイアウト自身に `row`・`col`・`rowspan`・`colspan` を指定し、親グリッド内の配置範囲を表す。

## セルの位置と範囲

次の既定値・検証規則を提案する。

| プロパティ | 意味 | 値 | 子レイアウトで省略した場合 |
| --- | --- | --- | --- |
| `row` | 親グリッドの開始行 | 0以上の整数 | 0 |
| `col` | 親グリッドの開始列 | 0以上の整数 | 0 |
| `rowspan` | 占有する連続した行数 | 1以上の整数 | 1 |
| `colspan` | 占有する連続した列数 | 1以上の整数 | 1 |

これらは**親のグリッド**を参照する。子自身の `row-definitions`・`column-definitions` は、割り当てられた領域を子がどう分割するかを指定する。親で2行・2列を占有していても、子の内部は1行・1列でよい。

親が `grid-layout` のときにセル指定を使う。`box-layout` には行・列がないので、その直下ではセル指定を使わず、padding を除いた内側を子が使う。最上位やグリッド以外の親の下でセル指定を与えた場合は、無視せずエラーにする案とする。box-layout の子を複数並べたい場合は、間に grid-layout を置く。

## 記述例

以下は `layouts` セクションの抜粋であり、単独で読み込めるスタイルファイルではない。

```json
{
    "layouts": [
        {
            "id": "demoViewport",
            "type": "box-layout",
            "padding": {
                "top": "8px",
                "right": "8px",
                "bottom": "8px",
                "left": "8px"
            },
            "children": [
                {
                    "id": "mainGrid",
                    "type": "grid-layout",
                    "row-definitions": ["1rate", "1rate", "1rate"],
                    "column-definitions": ["1rate", "1rate", "1rate"],
                    "children": [
                        {
                            "id": "inspectorContents",
                            "type": "grid-layout",
                            "row": 0,
                            "col": 0,
                            "rowspan": 2,
                            "colspan": 2,
                            "row-definitions": ["1rate"],
                            "column-definitions": ["1rate"]
                        }
                    ]
                }
            ]
        }
    ]
}
```

`inspectorContents` は `mainGrid` の左上2行×2列の領域を使う。その領域を、内部では1行×1列として使う。binding の参照先は `"layout": "demoViewport.mainGrid.inspectorContents"` になる。

## 配置計算と検証

親の行・列の幅は従来どおり `px` と `rate` から求める。開始列の左端から終了列の右端、開始行の上端から終了行の下端までを、子に割り当てる矩形とする。開始セルの幅・高さを span 倍する計算にはしない。行高・列幅が異なる場合も、占有範囲の各トラックの実寸を合計する。

その後、子が box-layout なら、子自身の padding などを適用して内側領域を求める。親の padding を子で再度差し引かない。

- `row + rowspan` が親の行数、`col + colspan` が親の列数を超える指定はエラー。実装では整数の加算オーバーフローも避ける。
- 小数・負数・文字列・null はエラー。span の 0 もエラー。省略と不正な値を区別する。
- 兄弟の占有範囲の重複はエラーとする案。開始セルが異なっていても、span の途中で重なる場合を検出する。
- 子レイアウトと、その親グリッドへ直接配置する文房具との範囲重複も検査する。子の内部に配置する文房具は、親の兄弟要素として重複判定しない。
- 領域外の指定を、自動的に切り詰めたり行・列の追加で補ったりしない。

## パスと既存ファイルとの互換性

Id は同じ親の下で一意とし、別の親の下では同じ Id を使える方針とする。Id 自体にはドットを使わない。存在しないパスや不完全なパスを、末尾の Id の全体検索で補完しない。

`children` を持たない既存のレイアウト定義と、最上位 Id だけの `bindings.layout` は引き続き有効にする。

現在の `bindings.childrenModel` は `row`・`column` を使う。拡張時は `col` を追加し、`column` は互換用の別名として受け付ける案とする。両方を指定した場合は曖昧さを避けるためエラーにする。既存の binding で必須だった開始位置の指定は維持し、`rowspan`・`colspan` だけを省略時1として追加する。文房具も、子レイアウトと同じ規則で複数セルに跨れるようにする。

## 実装前に合わせる点

この文書の既定値・重複禁止・互換用別名は提案である。ネスト全体の導入では、親レイアウトの基準領域をどの binding が与えるか、子の binding が親の領域を上書きしないこと、box-layout の子の個数、split-pane・ページレイアウトの子の配置規則も合わせて確定する。

パーサーだけでなく、配置エンジン、エディターのツリー・プレビュー・Id変更・削除・保存、利用者向け仕様、検証を揃えてから対応済みとして案内する。
