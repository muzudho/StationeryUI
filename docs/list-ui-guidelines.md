# リストUI設計の目安

## 10件以下のリスト

項目数が10件以下のリストは、必要に応じてスクロールバーを付け、ページャーは設けないことを基本とします。手動の並び替えには［上へ］［下へ］ボタンを使います。狭い領域では ↑・↓ のアイコンボタンにし、操作説明とアクセシブルな名前を付けます。

これは「並び替えの移動ボタンなら最悪50回程度まで押す」という設計上の仮定から決めた目安です。実測による万人共通の操作負担の上限ではありません。11件以上は禁止せず、検索、ドラッグ移動、移動先指定などを用途に応じて検討します。件数だけを理由にページャーを必須にはしません。

## 最悪の並び替え回数

1回の押下で、選択項目を隣の項目と交換し、上下に1段だけ移動するものとします。最悪回数とは、各初期順序から目標順序へ必要最小限の操作で並び替えるとき、その最小回数の最大値です。無駄な往復を含めれば回数に上限はありません。

目標と逆順のリストでは、すべての項目の組が逆転しています。隣接交換1回で解消できる逆転は1組なので、必要回数は次の通りです。逆転を1つずつ解消すればこの回数で完了できるため、下限だけでなく達成可能な最悪値でもあります。

```text
M(n) = (n − 1) + (n − 2) + … + 1
     = n(n − 1) / 2

M(n) ≤ 50
n² − n − 100 ≤ 0
n ≤ (1 + √401) / 2 ≈ 10.512

最大の整数 n = 10
```

| 項目数 n | 最悪の移動ボタン押下回数 M(n) | 50回以下 |
| --- | ---: | --- |
| 9 | 36 | ○ |
| 10 | 45 | ○ |
| 11 | 55 | × |

一般に許容移動回数を B としたとき、最大件数は `floor((1 + √(1 + 8B)) / 2)` です。

## 数える操作と実装上の配慮

- 回数に含むのは［上へ］［下へ］の押下だけです。項目選択、スクロール、ページ移動、保存などのクリックは含みません。「全クリックが50回以内」という保証ではありません。
- 先頭の［上へ］、末尾の［下へ］を無効にし、端から反対端へ回り込ませません。
- 移動後も同じ項目を選択し続け、表示範囲の外へ移動したらスクロールを追従させます。連続して押して移動できます。
- 保存対象のリストなら順序も保存し、取り消し・やり直しに対応させます。
- 並び替えと採点順・名前順などの自動ソートを混在させず、現在どの順序を表示しているか分かるようにします。

この目安は CircleSpaceCoordinator のフレーム配置案リストの設計相談（2026-09-13）をもとに整理しました。
