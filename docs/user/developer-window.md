# F12 開発者ウィンドウ

デモ画面がアクティブな状態で **F12** を押すと、別ウィンドウに文房具の階層が開く。
Debug／Release の両方で使える。既に開いている場合は同じウィンドウを前面に出す。
開発者ウィンドウ内の **F12**、**Esc**、または閉じるボタンで閉じる。デモへ戻って F12 を押せば再度開ける。
デモ終了時は開発者ウィンドウも終了する。

ウィンドウには文房具のツリーと詳細を表示する。
ツリーノードは `(文房具Id : 種類) (レイアウトの種類、または col, row, colspan, rowspan)` の形式で表示する。例えば `(demoPage : Page) (gridLayout)`、`(btn123 : Button) (1, 1, 1, 1)`。`col` と `row` は設定ファイルと同じ **0 始まり**で、span はセル数。レイアウトを持つノードはその種類を優先し、複数ある場合はカンマで並べる。レイアウト情報がないノードは `(—)`、非表示のノードは末尾に `（非表示）` を付ける。
左に文房具の階層、右に読み取り専用の詳細、下に「パスをコピー」を配置する。
ウィンドウ最下部には高さ **80px** の［インスペクターパネル］を置き、その中の［ツールヒント欄］に操作説明を表示する。マウスを部品に合わせるとその操作説明へ切り替わり、外すと通常の案内へ戻る。ページタイトルの下には操作説明を置かない。
この配置は文房具 UI の[おすすめのスタイルガイドライン](inspector-panel-guide.md)であり、利用アプリに必須ではない。
中央の仕切りをドラッグすると、階層と詳細の幅を調整できる。

- ツリーの［＋］［－］で枝を開閉。ホイールや幅 17px のスクロールバーで移動できる。
- ノードの文字が横に収まらない場合は、下端の横スクロールバーや Shift＋ホイールで横移動できる。
- Tab でツリー・仕切り・詳細・コピーボタンへ移動。ツリーは矢印キー、仕切りは左右キーでも操作できる。
- 詳細は長いパスを折り返して表示する。ホイール、スクロールバー、上下／PageUp／PageDown／Home／End で読み進められる。
- 詳細にフォーカスして Ctrl+C を押すと、詳細全体をコピーできる。パスだけ欲しいときは「パスをコピー」を使う。
- スナップショットの更新で選択や枝の開閉状態はリセットされない。F12 / Esc で隠して再表示した場合も、選択と分割位置を保つ。

ツリーから文房具を選ぶと、次の情報を確認できる。

- 文房具 Id と完全パス
- 種類と名前
- 表示中／非表示
- ウィンドウ内の位置と大きさ（px）

「パスをコピー」で完全パスをコピーできる。情報は実行中に更新される。
未表示のダイアログも「非表示」として表示する。ツリーの選択はデモ側の操作や入力フォーカスを変更しない。
表示状態は表示の有無を示すもので、モーダルによる操作可否や、他ウィンドウによる遮蔽は含まない。

## キャプチャーで部品を調べる

上部の指でつまむアイコンを押すとキャプチャーモードになる。調べたい部品を元の画面でクリックすると、桃色の枠で囲み、ツリーの該当ノードを「選択」と「操作対象」にする。閉じた親は開き、該当行までスクロールする。

詳細には `applePanel.bananaSubpanel.cherryComponent` のようなドット区切りの Id パスも表示する。キャプチャー中のクリックは部品の通常操作には使われない。手のアイコンをもう一度押すと解除する。

NuGet パッケージを使う別のアプリでは、アプリ側でクリック判定と桃色の枠の描画を接続する必要がある。アイコンを押しても部品を選べない、または枠が出ない場合は、[導入ガイドの［指でつまむ］機能](../dev/library-integration.md#f12-開発者ウィンドウと指でつまむ機能の組み込み)を確認する。

## 操作ログ

開発者ウィンドウの通常起動でも、操作の履歴を自動保存する。Windows の既定の保存先は `%LOCALAPPDATA%\StationeryUI\Logs`。エクスプローラーのアドレス欄へこのパスを入力すると開ける。ファイル名は `inspector-日時-プロセスID-識別子.jsonl` で、開発者ウィンドウの起動ごとに新しく作る。

クリックの押下・解放、ドラッグ、ホイール、操作用キー、入力受付状態、選択・操作対象のパス、枝の開閉、スクロール、仕切り位置、キャプチャーモードの変化を、UTC 時刻と連番付きで記録する。非アクティブ中に観測した入力も記録するが、記録したことはその操作を実行したことを意味しない。コピーした文章や一般の文字入力は保存しない。

問題を再現したら、その時刻付近の `.jsonl` を確認する。8 MiB に達すると直前の内容を同名の `.jsonl.1` に移し、記録を続けるため、両方あれば両方を使う。これは開発者ウィンドウ側のログであり、背景のゲーム側の操作ログとは別。修正前の実行ファイルで行った操作は遡って記録されない。

保存先を変える場合は、起動前に環境変数 `STATIONERYUI_OPERATION_LOG_DIR` にフォルダーを指定する。

## 文房具 Id の命名

文房具 Id は、アプリ側で用意された部品の識別名。開発者ウィンドウでは登録・編集せず、調べたい部品の名前と階層を確認する。

- 許可する文字は ASCII の `A-Z`、`a-z`、`0-9`、`_` のみ。空文字は不可。
- 基本の命名は `nameField`、`saveButton` のような **camelCase**。
- 大文字小文字は区別する。camelCase は命名規約で、許可文字の検査とは別。
- 同じ親の直下では Id を重複させない。別の親の下なら同じ Id を使用できる。

Id の重複や禁止文字は登録時にエラーにする。自動で連番を追加して別名に変えることはしない。

## パスで外側から辿る

```text
/demo
    /topDemoPage
        /nameField
        /memoField
        /editDialog
            /nameField
            /saveButton
```

デモには同じ `nameField` があるが、次の完全パスなら一意になる。

```json
[
    "/demo/topDemoPage/nameField",
    "/demo/topDemoPage/editDialog/nameField"
]
```

先頭の `/` からルート Id、親 Id、対象 Id の順に辿る。区切りの `/` は Id 自体には含まれない。
同じページを複数配置するときも、その外側のコンテナーやページインスタンスに別々の Id を付ければよい。
短い Id の全体検索、ワイルドカード、`..`、末尾の `/` は現時点で対応しない。

スタイル JSON の bindings でこのパスを指定し、文房具をレイアウトのセルに配置できる。
配置後の座標もこのウィンドウで確認できる。色やフォントの個別指定は未対応。
