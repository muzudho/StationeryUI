# インスペクターパネルとツールヒント欄

文房具 UI の作業画面では、画面の下端に高さ **80px**、画面いっぱいの横幅を持つ「インスペクターパネル」を置くことを**推奨**します。これはおすすめのスタイルガイドラインであり、必須要件ではありません。用途に合わせて採用・調整できます。

名称は「インスペクターパネル」に統一します。操作説明や状態をまとめる常設の領域を表し、分割操作を伴う「スプリットペーン」と区別しやすくするためです。その中に「ツールヒント欄」を置き、操作説明とマウスカーソルを合わせたコントロールの説明を表示します。ページタイトルの下など、作業エリアには操作説明を常設しないことを推奨します。

開発者ウィンドウもこの配置を採用しています。タイトルとキャプチャーボタンは上部、階層と詳細は作業エリア、操作説明は下端のツールヒント欄に表示します。ホバー中は対象の説明を優先し、カーソルを外すとキャプチャー状態に応じた案内に戻ります。

## 画面の作り方

- 先に下端の 80px を確保し、その上の領域へ編集欄・ツリー・プレビューなどを配置します。パネルを編集内容の上へ重ねません。
- 80px はビューポートのピクセル数です。UI の拡大率に比例して高さを変えず、ウィンドウサイズが変わったら位置と横幅を更新します。
- 常設の長い操作説明はツールヒントへ移します。コントロール名、入力項目名、単位、編集中の対象など、操作対象を見分けるためのラベルは残します。
- 説明は「押すと何が起きるか」「何を入力するか」「単位や条件」を短い文で書きます。例：「px は固定サイズ、rate は残りの領域を分け合う比です。」
- 無効なコントロールにも説明を出します。例：「先にフォルダーを選択してください。」無効になっている理由と、使えるようにする操作を伝えます。
- カーソルを外したら以前の説明を消し、案内の初期表示へ戻します。モーダルダイアログを開いている間は、背面の説明を出しません。

入力エラー、重複 Id、警告、保存結果などは一時的なホバー説明とは別に扱います。重要な結果がホバーで消えないよう、パネルの別行や入力ダイアログ内へ表示します。スタイル設計ツールでは、上の56pxをツールヒント、下の24pxを状態・結果の欄にしています。

オートセーブがある画面では、状態欄に保存開始までの待ち時間バーと保存状態を置きます。スタイル設計ツールは下段右側に配置し、最後の変更から1.5秒で満杯になります。これは書き込み量の進捗ではありません。保存失敗時は赤いバーと理由を表示し、未保存の入力を保持します。

## スタイル設定

作業ページを定義する際は `work-page-layout` の `inspectorHeight` を `"80px"` とし、`bindings` で本文とは別の inspector 用モデルを指定できます。本文の余白でパネルの横幅を狭めないようにします。具体的な定義は [スタイル設定のページレイアウト](stationery-ui-settings.md) を参照してください。

操作説明の内容はアプリ側で設定します。配置用 JSON だけでは C# の操作内容を推測できません。
