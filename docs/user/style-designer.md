# スタイル設計ツール

文房具 UI で作る画面のプランを GUI で組み立て、`*.stationery-style.json` を出力する独立アプリ。
出力した JSON を AI コーディングへ渡し、「この設計で C# の画面を作って」と依頼する。
既存ファイルを読み込んで編集することもできる。結果は別名でエクスポートし、元のファイルは変更しない。C# の生成は行わない。

## 使い方

1. １ページ目で「新規作成」または「既存のファイルを編集する」を選ぶ。後者では Windows のファイル選択ダイアログからファイルを選ぶ。キャンセル時や読み込み失敗時は１ページ目に留まり、現在のプランを保持する。
2. ２ページ目の左側にスタイル全体のツリー、右側に編集画面が表示される。新規作成では横のセル数（列数）と縦のセル数（行数）を入力し、「表を作る／更新」を押す。各 1～8 セル。
3. 表の上で各列の幅、左で各行の高さを指定する。数値は入力欄、単位は `rate`／`px` の切り替えボタンで指定する。
4. 新規作成では中央のセルをクリックし、下の種類ボタンで文房具を選ぶ。空き領域・ボタン・テキスト入力・説明テキスト・ページリンク・ツリーを選べる。表示名も入力できる。
5. サイズのプレビューを確認する。中央は編集しやすい等間隔の表、下のプレビューは指定した行列のサイズ配分を表す。下の図は横・縦をそれぞれ表示領域へ縮めているため、実際の画面の縦横比を表すものではない。
6. 存在するフォルダー内の新しい出力先を指定し、「エクスポート」を押す。拡張子は `.stationery-style.json`。既存ファイルは上書きしない。

２ページ目の出力欄には次のボタンがある。

- 「エクスポート」：出力先欄のパスへ現在の設計を出力する。
- 「フォルダーを選ぶ」：Windows のフォルダー選択ダイアログで新規作成先を選ぶ。キャンセル時は選択を保持する。
- 「ファイルを選ぶ」：既存の JSON を開き、現在のプランを置き換える。必要な編集結果は先にエクスポートする。キャンセルや読み込み失敗時には置き換えない。
- 「新規作成」：選択フォルダーに現在の設計を `my-plan.stationery-style.json` として作成する。同名があれば `my-plan-2.stationery-style.json` のように連番を付ける。フォルダー未選択時は無効となり、「先にフォルダーを選択してください」と表示する。

出力は UTF-8（BOM なし）、インデントは４スペース。各行の改行が二重にならないよう正規化する。

「1 ページ目へ戻る」で選択画面に戻り、「現在の編集を再開」でプランを保ったまま戻れる。「新規作成」や別ファイルの読み込みは現在のプランを置き換える。

## 既存ファイルとスタイルツリー

ツリーの水色の枠は「操作対象」を表す。この画面では緑の背景で表す「選択」は使わない。クリックや矢印キーで操作対象を移動できる。

- 操作対象がトップ階層の `layouts` のときだけ「子要素追加」が有効になる。ダイアログで `panel` または `floating-layout` を選ぶ。キャンセルや Esc では追加しない。
- `floating-layout` を追加すると既存のグリッド設定画面へ移る。行列数と数値・単位を入力する。
- `panel` を追加すると `margin`、`padding`、`border` の top / right / bottom / left を px で入力する画面へ移る。既存の panel もツリーから開ける。
- 追加ダイアログの「文房具Ｉｄ」で Id を指定する。初期値は重複しない `layout1` など。追加したレイアウトは独立した定義で、bindings やモデルは自動追加しない。
- 「削除」は操作対象がない場合とトップ階層では無効。子要素では有効だが、参照中のレイアウトや必須プロパティなど、設定を不正にする削除はエラーを表示して取り消す。参照がある場合は該当する binding を先に削除する。

追加・削除・余白編集の結果はメモリー上のプランに反映される。ファイルに残すにはエクスポートする。

ツリーでモデルまたはレイアウトのノードを操作対象にすると、下の「Ｉｄ変更」で名前を変更できる。Id を持たないトップ階層・プロパティ・binding では無効。モデルの子孫を含む bindings の参照も追従する。独自の追加プロパティ内に書いた参照文字列は自動変更しない。

Id は半角の英字大文字・小文字、数字、アンダースコアのみ使用できる。空文字・その他の文字・同じ親にある既存 Id との重複は確定できず、ダイアログに理由を表示する。大文字小文字は区別し、別の親の子同士で同じ Id を使うことはできる。

推奨は `myPanel2` のような camelCase。数字始まり、アンダースコア、大文字始まり、連続する大文字や末尾の大文字などは警告を表示するが、そのまま確定できる。キャンセル時は元の Id と内容を保持する。

左側は `models`・`layouts`・`bindings` と追加設定をツリー表示する。＋／－で展開・折り畳み、スクロールバーや矢印キーで移動できる。正常な編集内容をツリーへ反映し、入力途中でエラーがある間は直前の有効な表示を保つ。
`layouts` 内の 8×8 以下のフローティングレイアウトを選ぶと、右側の表を切り替えられる。別のレイアウトへ移動しても、変更済みのサイズは保持する。
既存ファイルでは行・列のサイズとセル数が編集対象。モデルの Id・種類・表示名・階層や bindings、panel・split-pane・ページレイアウト、追加のプロパティは保持する。既存セルには参照する文房具名を表示する。
配置済みの文房具が表の外に出る縮小は拒否する。行・列を増やしても既存モデルの追加や再配置は行わない。
編集可能なフローティングレイアウトがないファイルも開ける。その場合はツリーでの確認と別名出力ができる。

`1.5rate` は数値欄に `1.5`、単位に `rate` を指定する。px は固定サイズ、rate は残りの領域を分け合う比。
負数、数値欄への単位入力、全行／全列がゼロになる設定は出力できず、画面にエラーを表示する。
表を縮める操作は範囲外のセルを削除するため、同じセル数で更新をもう一度押すと確定する。
Tab で入力欄やボタンへ移動し、Enter／Space でボタンを操作できる。明暗テーマも切り替えられる。
操作ボタンには文房具 UI の共通ボタン描画を使用する。四辺の枠、ホバー・押下・フォーカス表示があり、下線付きの数値・テキスト入力欄と区別できる。`rate`／`px` も単位選択用のボタン。

## AI に渡す設計図

モデルの Id は `cellR1C1` のように位置から自動生成される。人が Id を入力する必要はない。
`models` に文房具の種類と `label`、`layouts` に行列のサイズ、`bindings` にセルへの配置を出力する。
`label` は設計用の表示名。現行のスタイルローダーはこれを描画へ自動反映しないため、AI が C# のラベルや初期テキストとして接続する。
ボタンの動作、リンクの遷移先、ツリーの内容などは、JSON と一緒に AI へ別途指示する。

新規作成は一つのページ・一つのフローティングレイアウトから始まる。レイアウトを追加すると既存モデルを保持する編集へ移行する。複数の表や panel をツリーで切り替えられる。スプリットペーンなど他のレイアウト種類はツリーでの確認のみ。
作業中のプランはメモリー上にあるため、終了前にエクスポートする。

## 起動と配布

起動時はマウスカーソルのあるディスプレイの作業領域（タスクバーを除いた範囲）に合わせ、ウィンドウ枠・タイトルバーと周囲の余裕を確保して中央付近に表示する。編集領域は最大 1600×900 で、小さいディスプレイでは画面全体を縮小表示する。起動後は手動でサイズを変更できる。

GitHub Release の Windows x64 ZIP は .NET ランタイム同梱版。ZIP を新しいフォルダーへすべて展開し、その中の `StationeryUI.StyleDesigner.exe` を起動する。別途 .NET をインストールする必要はない。EXE だけを取り出さず、DLL・licenses などを含むフォルダー全体を使う。

v0.1.0 の設計ツールは未署名で配布する。Windows の保護機能によって起動可否が異なる場合がある。

ソースからの起動：

```powershell
dotnet run --project samples/StationeryUI.StyleDesigner -c Release
```

リリース用の出力：

```powershell
dotnet publish samples/StationeryUI.StyleDesigner -c Release --self-contained false -o artifacts/release/style-designer
```

上記コマンドによるランタイム非同梱版は、出力フォルダー全体から `StationeryUI.StyleDesigner.exe` を起動する。こちらは Windows 用の .NET 8 Desktop Runtime が必要。
設計ツールは文房具 UI の DLL を利用するが、文房具 UI の NuGet パッケージに設計ツールは含めない。
