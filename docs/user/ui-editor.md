# 文房具UIエディター

引数なしで起動すると「新規作成」「既存ファイルを読み取る」の開始画面を表示します。ファイル選択後は読取モードになり、モデル／レイアウト／JSON ツリーとプレビュー、切り替え可能な詳細を確認できます。「編集を開始」を押すと編集モードへ移り、その時点でセーブポイントを作ります。読取モードでは元ファイルを更新せず、バックアップも作りません。

読取画面と編集画面は同じ配色で、実行中の対象やプレビューの操作対象を水色の枠、margin の外側を細い水色の線、レイアウトの分割を桃色の点線で示します。読取画面の margin／padding 図は設定値の確認用で、値の変更は編集画面の入力欄で行います。
読取画面では右側にレイアウトプレビューを表示します。左のツリーで子要素を選ぶと、親要素を桃色の枠、親レイアウトの子要素を仕切る線を桃色の点線、選んだ子要素を水色の枠で示します。右上の「詳細を見る」／「プレビューを見る」で、余白の図を含む詳細とプレビューを切り替えられます。

起動引数に文房具UIファイルを1つ渡す従来の形式は、編集画面で起動します。例：`StationeryUIEditor.exe "D:\plans\demo.stationery-ui.json"`。読取で直接開くには `StationeryUIEditor.exe --mode read --file "D:\plans\demo.stationery-ui.json"` を使います。デモの **F12** は実行中の画面につながる読取モード、**Ctrl＋F12** は同じウィンドウの編集モードです。編集を開始すると元ファイルへのオートセーブが有効になります。
デモから開いた画面では、上部にアプリ側の反映状態を表示します。編集画面の保存状態とは別で、「保存済み。アプリの再読込を待っています」「アプリへ反映済み」「アプリの再読込失敗」などを確認できます。
読取画面と編集画面を切り替えると、モデル／レイアウトツリーで選んだ対象と枝の開閉を引き継ぎます。JSON ツリーを選ぶと右側に JSON パスと値の概要を表示し、対応するモデルがあればプレビューの対象も切り替えます。JSON ツリーで選んだ項目は、読取／編集の切替後も同じ JSON パスを選びます。モデルとの対応がない設定項目は JSON として閲覧できます。
読取中に文房具UIファイルの内容が変わると、プレビューを自動で読み直します。更新日時が同じでも内容で検出します。一時的に読めない場合や JSON が不正な場合は直前の有効な表示を残し、修復後に再読込します。

画面上部の **ページ編集** から、英小文字で始まる名前の空ページを追加できます。ページ一覧で選んで **選択したページを削除** を2回押すと削除します。最後の1ページは削除できません。追加・削除は元ファイルへ自動保存されます。現時点では、単一の `viewports` に `Page` が並び、対応する `modelTree` があるファイルを対象にしています。追加したページには空のボックスレイアウトが付きます。デモアプリのページ遷移はC#側の実装なので、新しいページをデモで表示するには別途遷移処理が必要です。

レイアウト型 `panel` は `box-layout`（ボックスレイアウト）に改称しました。旧名も読み込めますが、保存時は新名を出力します。margin・border・padding の役割は同じです。画面下の「インスペクターパネル」という領域名は引き続き使用します。新形式のファイルを扱う場合は、対応版のエディターを使用してください。

リポジトリー版では「フローティングレイアウト」を「グリッドレイアウト」に改称しました。旧形式の `floating-layout` も開けます。保存時は `grid-layout` として出力します。公開済みの旧版エディターで新形式を開けるとは限らないため、共同編集時は対応版を揃えてください。

文房具 UI で作る画面のプランを GUI で組み立て、`*.stationery-ui.json` を出力する独立アプリ。
出力した JSON を AI コーディングへ渡し、「この設計で C# の画面を作って」と依頼する。
既存ファイルを読み込んで編集することもできる。読み込み時にセーブポイントを作り、変更は元ファイルへオートセーブする。C# の生成は行わない。

現在の２ページ目は `layouts` の設定専用。`models` と `bindings` はツリーとプレビューで参照できるが、直接編集・削除・Id変更はできない。文房具の種類・表示名を編集する欄も表示しない。レイアウトのId変更に伴う参照更新は引き続き自動で行う。

## 使い方

画面下には高さ80pxのインスペクターパネルがある。コントロールにマウスを合わせるとツールヒント欄へ操作説明を表示する。無効なボタンでは有効にする条件も確認できる。保存結果や入力エラーはパネルの別行に表示する。[設計ガイド](inspector-panel-guide.md) を参照。

２ページ目の上端には、高さ40px・画面いっぱいの幅の「アプリケーションバー」がある。「明るい／暗い」「1 ページ目へ戻る」「セーブポイントに戻す」「エクスポート」をここにまとめる。本文はバーとインスペクターの間に配置する。左の見出しは「スタイルツリー」。長い編集タイトルや操作説明は常設せず、操作説明はインスペクターへ表示する。

表の設定は「列の幅」「行の高さ」の２列に揃え、それぞれの下に「列数」「行数」と各列・行のサイズ入力欄を配置する。有効な列数・行数は自動反映される。「表を作る／更新」ボタンは廃止した。縮小するときは確認ダイアログが開き、「縮小する」で範囲外のセルを削除する。「閉じる」または Esc では元の列数・行数に戻る。空欄や1～8以外の値は反映せず、インスペクターへ理由を表示する。

1. １ページ目で「新規作成」または「既存ファイルを読み取る」を選ぶ。後者では Windows のファイル選択ダイアログからファイルを選び、読取画面の「編集を開始」で編集へ進む。キャンセル時や読み込み失敗時は１ページ目に留まり、現在のプランを保持する。
2. ２ページ目の左側にスタイル全体のツリー、右側に編集画面が表示される。横のセル数（列数）と縦のセル数（行数）を入力すると自動反映される。各 1～8 セル。
3. ツリーの隣にある列幅・行高の入力欄で設定する。数値は入力欄、単位は `rate`／`px` の切り替えボタンで指定する。
4. 右側のプレビューでサイズ配分を確認する。セルをクリックすると水色の枠で確認対象を示す。文房具の種類や表示名はこの画面では編集しない。
5. プレビューの配置は入力と連動する。従来の等間隔の設定テーブルと下部のサイズ配分欄は、実際の配置でセルを選ぶ編集プレビューに統合した。入力欄は小さいセルや幅 0 の列も変更できるよう、隣に固定表示する。
6. 新しいプランでは、アプリケーションバーの「エクスポート」でダイアログを開く。存在するフォルダー内の出力先を指定し、「書き出す」または「新規作成」で最初の保存をする。以後はそのファイルへ自動保存する。既存ファイルを開いた場合は最初から自動保存が有効。拡張子は `.stationery-ui.json`。

２ページ目の出力先欄はエクスポートダイアログ内にある。次の操作ができる。

ダイアログ表示中は、背面に半透明の黒い幕を表示し、ダイアログの外周を枠で示す。エクスポート、縮小確認、子要素追加・Id変更、セーブポイント選択はすべてモーダルで、背面のボタン・ツリー・入力欄・プレビューは操作できない。キーボード入力も表示中のダイアログだけが受け取る。閉じるボタンまたは Esc で通常の操作に戻る。

- 「エクスポート」（アプリケーションバー）：出力先のパスと保存操作をまとめたダイアログを開く。
- 「書き出す」（ダイアログ内）：出力先欄のパスへ現在の設計を出力し、そのファイルを自動保存先にする。編集中の元ファイルと同じパスなら即時保存する。それ以外の既存ファイルは上書きしない。
- 「フォルダーを選ぶ」：Windows のフォルダー選択ダイアログで新規作成先を選ぶ。キャンセル時は選択を保持する。
- 「ファイルを選ぶ」：現在のファイルの変更を保存し、選んだ JSON のバックアップを作って開く。まだ保存先のないプランは先にエクスポートする。キャンセルや読み込み失敗時には置き換えない。
- 「新規作成」：選択フォルダーに現在の設計を `my-plan.stationery-ui.json` として作成する。同名があれば `my-plan-2.stationery-ui.json` のように連番を付ける。フォルダー未選択時は無効となり、マウスを合わせると「先にフォルダーを選択してください」とツールヒント欄に表示する。
- 「セーブポイントに戻す」（アプリケーションバー）：ファイル名と変更日時の一覧からバックアップを選び、「このセーブポイントに戻す」で復元する。元ファイルも復元内容に更新する。キャンセルでは変更しない。保存先が未決定の間は無効。

出力ファイルは UTF-8（BOM なし）、インデントは４スペース。

「1 ページ目へ戻る」で選択画面に戻り、「現在の編集を再開」でプランを保ったまま戻れる。「新規作成」や別ファイルの読み込みは現在のプランを置き換える。

## オートセーブとセーブポイント

`banana.stationery-ui.json` を開くと、同じフォルダーに `banana.stationery-ui.json.1.bak` を作る。次に開いたときは `.2.bak`、`.3.bak` と番号を増やす。新規出力の最初の保存時にもセーブポイントを作る。最大20世代を保持し、それを超えると番号の古いものから削除する。通常のオートセーブごとにはバックアップを増やさない。

最後の変更から **1.5秒** 待って、編集中の元ファイルへ上書き保存する。インスペクター右下のタイマーバーが伸び、保存済みでは満杯になる。バーは保存開始までの待ち時間を表す。保存先は「保存済み」のファイル名で確認できる。出力先欄やフォルダー選択だけでは自動保存先は切り替わらず、書き出す／新規作成を実行したときに切り替わる。

ダイアログ表示中・IME変換中・不正な入力の間はタイマー保存を待つ。１ページ目へ戻るとき、別ファイルを開くとき、終了するときは待ち時間を省いて保存する。保存できない場合は編集内容を保持して移動・終了を止める。ダイアログは閉じてから終了する。

破棄したい場合は「セーブポイントに戻す」を使う。一覧の日時はバックアップ元のファイル変更日時をローカル時刻で表示する。復元直前の有効な編集内容も別世代に退避するため、戻しすぎた場合はその世代を選び直せる。不正な入力途中の文字列はバックアップ対象に含まない。

保存失敗時はバーが赤くなり理由を表示する。通常画面では1.5秒間隔で再試行する。外部で元ファイルが変更された場合は上書きを停止する。現在の設計を別名でエクスポートして確保してから、必要なファイルを開き直す。

## 既存ファイルとスタイルツリー

プレビューは設定欄の右側からウィンドウ右端の8px手前まで、下端はインスペクターパネルの8px手前まで広がる。ウィンドウを広げると表示領域も広がる。

編集プレビューは JSON の `models`・`layouts`・`bindings` を使い、プレビュー領域自体の実ピクセル数をビューポートサイズとして配置する。サイズは見出しに表示される。ウィンドウサイズを変えると再計算され、px は固定サイズ、rate は残りの領域を分配する。1000×600 の固定サイズや縦横別の縮小は使用しない。

選んだレイアウトが割り当てられたページを表示する。まだ binding がない box-layout / grid-layout は「未割り当ての定義」と表示して単体プレビューする。このための仮モデルはプレビュー専用で、エクスポートには追加しない。box-layout の内側領域やグリッドのセル境界は水色の編集ガイドで示す。

ボタン・リンク・入力欄・ツリー・スプリットペーンなどを種類に応じて表示する。表示名は JSON の label、なければ Id を使う。C# 側のクリック処理、ページ遷移、ツリーの実データなどは実行しない。プレビューのクリックは編集対象セルの指定として扱う。

ツリーの水色の枠は「操作対象」を表す。この画面では緑の背景で表す「選択」は使わない。クリックや矢印キーで操作対象を移動できる。

## ツリー表示の変更（after v0.3.0）

- ツリーのノード表示は簡潔化し、画面上のツリーには文房具名（nodeName）のみを表示する。Id・種類・配置・レイアウト種別を1行に連結して表示しない。
- ノードの詳細は、ツリー右側の編集領域上部にあるプロパティ欄で確認する。プロパティ欄は読み取り専用で、次の4項目を表示する。
  1. 文房具Ｉｄ
  2. 種類
  3. コンテナー内の位置（`col=` / `row=` / `colspan=` / `rowspan=`）または `-`
  4. コンテナーとしてのレイアウト（`boxLayout` / `dockLayout` / `gridLayout`）または `-`
- この変更は表示のみで、JSON スキーマや内部識別子（Id / Path）の仕様は変更しない。

２ページ目を開いたときは、初期表示するレイアウトに水色の操作対象枠を付ける。新規プランでは `mainGrid`、既存ファイルでは読み込み時に選ばれた編集可能なレイアウトが対象になる。プレビュー見出しにも対象のIdを表示する。レイアウト内のプロパティを操作対象にした場合は、そのレイアウトを表示する。操作対象がない場合や、models・bindings・トップ階層などを操作対象にした場合は、設定欄とプレビューを空にする。

- `layouts`、子のない `box-layout`、または `grid-layout` を選ぶと「子要素追加」が有効になる。種類とIdを指定し、グリッド内では row・col・rowspan・colspan も入力する。キャンセルや Esc では追加しない。[ネストの操作](nested-layouts.md)を参照。
- `grid-layout` を追加すると既存のグリッド設定画面へ移る。行列数と数値・単位を入力する。
- `box-layout` を追加すると `margin`、`padding`、`border` の top / right / bottom / left を px で入力する画面へ移る。既存の box-layout もツリーから開ける。
- 追加ダイアログの「文房具Ｉｄ」で Id を指定する。初期値は重複しない `layout1` など。追加したレイアウトは独立した定義で、bindings やモデルは自動追加しない。
- 「削除」は layouts 内の子要素で有効。models・bindings、トップ階層、操作対象がない場合は無効。参照中のレイアウトや必須プロパティなど、設定を不正にする削除はエラーを表示して取り消す。

追加・削除・余白編集の結果もオートセーブの対象になる。保存先が未決定の場合は、最初にエクスポートまたは新規作成を行う。

ツリーでレイアウトのノードを操作対象にすると、下の「Ｉｄ変更」で名前を変更できる。グリッド直下の子では、同じダイアログでセル位置と span も変更できる。models・bindings と、Id を持たないトップ階層・プロパティでは無効。子孫を含む bindings のレイアウト参照も追従する。独自の追加プロパティ内に書いた参照文字列は自動変更しない。

Id は半角の英字大文字・小文字、数字、アンダースコアのみ使用できる。空文字・その他の文字・同じ親にある既存 Id との重複は確定できず、ダイアログに理由を表示する。大文字小文字は区別し、別の親の子同士で同じ Id を使うことはできる。

推奨は `myPanel2` のような camelCase。数字始まり、アンダースコア、大文字始まり、連続する大文字や末尾の大文字などは警告を表示するが、そのまま確定できる。キャンセル時は元の Id と内容を保持する。

左側は `models`・`layouts`・`bindings` と追加設定をツリー表示する。＋／－で展開・折り畳み、スクロールバーや矢印キーで移動できる。正常な編集内容をツリーへ反映し、入力途中でエラーがある間は直前の有効な表示を保つ。
`layouts` 内の 8×8 以下のグリッドレイアウトを選ぶと、右側の表を切り替えられる。別のレイアウトへ移動しても、変更済みのサイズは保持する。
既存ファイルでは行・列のサイズとセル数が編集対象。モデルの Id・種類・表示名・階層や bindings、box-layout・split-pane・ページレイアウト、追加のプロパティは保持する。既存セルには参照する文房具名を表示する。
配置済みの文房具が表の外に出る縮小は拒否する。行・列を増やしても既存モデルの追加や再配置は行わない。
編集可能なグリッドレイアウトがないファイルも開ける。その場合はツリーでの確認と別名出力ができる。

`1.5rate` は数値欄に `1.5`、単位に `rate` を指定する。px は固定サイズ、rate は残りの領域を分け合う比。
負数、数値欄への単位入力、全行／全列がゼロになる設定は出力できず、画面にエラーを表示する。
表を縮める操作は範囲外のセルを削除するため、確認ダイアログの「縮小する」で確定する。
Tab で入力欄やボタンへ移動し、Enter／Space でボタンを操作できる。明暗テーマも切り替えられる。
操作ボタンには文房具 UI の共通ボタン描画を使用する。四辺の枠、ホバー・押下・フォーカス表示があり、下線付きの数値・テキスト入力欄と区別できる。`rate`／`px` も単位選択用のボタン。

## AI に渡す設計図

モデルの Id は `cellR1C1` のように位置から自動生成される。人が Id を入力する必要はない。
`models` に文房具の種類と `label`、`layouts` に行列のサイズ、`bindings` にセルへの配置を出力する。
`label` は設計用の表示名。現行のスタイルローダーはこれを描画へ自動反映しないため、AI が C# のラベルや初期テキストとして接続する。
ボタンの動作、リンクの遷移先、ツリーの内容などは、JSON と一緒に AI へ別途指示する。

新規作成は一つのページ・一つのグリッドレイアウトから始まる。レイアウトを追加すると既存モデルを保持する編集へ移行する。複数の表や box-layout をツリーで切り替えられる。スプリットペーンなど他のレイアウト種類はツリーでの確認のみ。
保存先が未決定の新しいプランはメモリー上だけにあるため、終了前に最初の保存を行う。保存先が決まったプランは終了時にも未保存の変更を保存する。

## 起動と配布

起動時はマウスカーソルのあるディスプレイの作業領域（タスクバーを除いた範囲）に合わせ、ウィンドウ枠・タイトルバーと周囲の余裕を確保して中央付近に表示する。編集領域は最大 1600×900 で、小さいディスプレイでは画面全体を縮小表示する。起動後は手動でサイズを変更できる。

ソースからビルドした場合は `StationeryUIEditor.exe` を起動する。公開済みの v0.4.0 ZIP は名称変更前の成果物なので、展開先の `StationeryUI.StyleDesigner.exe` を起動する。Windows x64 ZIP は .NET ランタイム同梱版で、別途 .NET をインストールする必要はない。EXE だけを取り出さず、DLL・licenses などを含むフォルダー全体を使う。

v0.2.0 の設計ツールは未署名で配布する。Windows の保護機能によって起動可否が異なる場合がある。

## 操作ログ

操作ログは `%LOCALAPPDATA%\StationeryUI\Logs` に `ui-editor-*.jsonl` として保存されます。クリックしたページ、画面上の座標、対象 UI のパス、ページ遷移の移動元と移動先を記録します。ファイル名だけを記録し、入力欄の文字列やファイルのフルパスは記録しません。
