# 【むずでょ個人用】READMEスタイル・ガイドライン

## ファイルについて

* 改行は Windows の `CRLF` で統一してください。
* 文字エンコードは `UTF-8（BOMなし）` で統一してください。

## ［ドキュメントの最初のページ］のスタイル・ガイドライン

ドキュメントの最初のページは、［ナビゲーション］という働きを持たせます。  
［どのような役割の人］が読むのかによって、ドキュメントへのリンクを用意してください。  

例えば、いかのような階層で目次を作り、リンクを置いてください。  

* `利用したい` - 配布物を利用したい人。［利用者］向けのドキュメントへのリンク
	* `すぐ使いたい` - 最新のリリース・ページへリンクしてください。
* `開発に貢献したい` - 成果物の改善に貢献したい人。［開発者］向けのドキュメントへのリンク
	* `開発日誌` - `docs/dev/log/` フォルダー下の最新のドキュメントへのリンク

［利用者］向けのドキュメントには、［開発者］向けの手順や実装の詳細は書かない。  
［開発者］向けのドキュメントには、［利用者］向けの手順や配布物の使い方は書かない。  
［ドキュメントの最初のページ］には、［利用者向けのドキュメント］と［開発者向けのドキュメント］へのリンクを用意する。  

そして、［利用者］は［開発者向けドキュメント］の内容を知らなくてもよいようにします。  
［開発者］には、［利用者向けドキュメント］の内容が役に立ちます。  

また、［利用者］向けのドキュメントを、［開発者］向けのドキュメントより先に置いてください。  

ディレクトリー階層の例です。  
* `{リポジトリー}`
	* `docs`
		* `user` - ここに［利用者向けドキュメント］を置く。
		* `dev` - ここに［開発者向けドキュメント］を置く。

👆　リポジトリーによっては、ディレクトリー名、ファイル名は PascalCase にする場合もあります。

## ［利用者］向けのドキュメントのスタイル・ガイドライン

例えば、以下のリンクを置きます。  

* `これはいつどのように使われるか` - `docs/user/{プロダクト名}/use-case.md` へのリンク
* `これはどのような製品か`

## ［ユースケース］ドキュメントのスタイル・ガイドライン

書き方は以下を参考にしてください。  
D:\github.com\muzudho\StationeryUI\docs\user\style-settings\use-case.md  

登場人物を定義し、使われる場面に沿ったシナリオを書いてください。
